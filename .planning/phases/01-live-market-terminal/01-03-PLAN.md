<objective>
Connect the page to the live price stream through one shared store and make the header live: connection dot (D-19), cash and live total value colored against the $10,000 start (D-08).

Purpose: after this plan a user sees the header go LIVE when the backend streams, RECONNECTING/OFFLINE when it does not, and their cash and total value. It also fixes the store contract (ticks, flash sequence, markers, session stats, buffers, formatters, API fetchers) that the watchlist (01-05) and chart (01-07) plans consume. Implements D-08, D-19, D-20 (browser-only history) and the OQ-1 resolution (flash driven by stream direction, de-duplicated by timestamp).
Output: `frontend/src/lib/{types,priceStore,format,api,usePortfolio}.ts`, `ConnectionIndicator`, `Header`, AppShell wiring, tests.
</objective>

## Phase Goal

ROADMAP goal (verbatim, not in user-story form; see plan 01-01): User starts the app with one script, opens http://localhost:8000, and watches the 10 default tickers stream live with flashing prices, sparklines and a main chart, next to a $10,000 portfolio.

## UI Considerations (from 01-UI-SPEC.md) handled in this plan

- error / connection indicator: covered (indicator half here; muted prices and suppressed flash are in plan 01-05).
- error and loading / header portfolio values: covered.
- overflow / header total at large magnitudes: backstop (must_haves).
- partial / hidden browser tab: dismissed. Reason (UI-SPEC): no special handling needed; EventSource keeps filling the buffers while hidden, skipped flashes are harmless and the chart is current on return.
